## Why

Os READMEs atuais documentam a entrega, mas a API está longa demais para uma avaliação técnica rápida e mistura instruções essenciais com justificativas, roadmap e conteúdo fora do interesse imediato do avaliador. A documentação deve ficar mais objetiva, fiel ao que foi implementado e fácil de usar para rodar, testar e validar a prova.

## What Changes

- Reescrever o README da API em formato enxuto, priorizando execução, variáveis, Swagger, endpoints, autenticação, regras de negócio, testes e diferenciais realmente implementados.
- Remover da documentação da API trechos de baixo valor para avaliação, como roadmap de CI/CD/deploy, defesa extensa contra microsserviços, padrão para novas implementações, registro histórico de decisões e listas especulativas de melhorias.
- Corrigir trechos que podem confundir o avaliador, especialmente qualquer indicação de que o frontend está fora do repositório/entrega quando há projeto frontend separado.
- Enxugar o README do frontend, removendo detalhes internos de teste, versão local de Node hardcoded e listas longas que não ajudam a rodar ou avaliar a solução.
- Manter nos dois READMEs apenas comandos reais, contratos relevantes e limitações objetivas que sejam úteis para a prova.
